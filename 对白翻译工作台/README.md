# 剧本对白翻译 · 本地工作台

把**纯中文的短剧 Word 剧本**批量翻成"**中上英下**"成品的一条龙本地工具（DeepSeek，可离线扩展）。

```
中文剧本 docx ──► ① 命令行翻译 ──► 双候选数据(_candidates_cache.json)
                    │
                    ▼           ② 浏览器工作台（可选但推荐）
                点选 A/B · 手改 · 跳过  ──► ③ 导出
                                               ├─ <剧>_成品_中上英下.docx
                                               └─ <剧>_成品_纯英.txt
```

---

## 文件清单

| 路径 | 作用 |
|---|---|
| `E:\desk\translate_docx.py` | **命令行翻译器**（单译文 / 双候选），纯 Python，无 UI |
| `E:\desk\对白翻译工作台\server.py` | 工作台后端（读剧本+候选、存你的选择、导出） |
| `E:\desk\对白翻译工作台\index.html` | 工作台前端页面（逐句点选/手改/跳过/导入剧本） |
| `E:\desk\对白翻译工作台\启动工作台.bat` | 双击启动（开浏览器 + 起服务） |

## 快速开始

### 第一步：装依赖（只装一次）
```bash
pip install python-docx requests
```
> 翻译用 DeepSeek key，读取环境变量 `ANTHROPIC_AUTH_TOKEN`（就是你 Claude Code 用的那把，已配好就不管）。

### 第二步（A）：命令行翻译成"中上英下"
```bash
cd E:\desk
python translate_docx.py --docx "鲨鱼剧本AI测试.docx"              # 单译文，全部集
python translate_docx.py --docx "鲨鱼剧本AI测试.docx" --eps 1-3     # 只翻1-3集
python translate_docx.py --docx "新剧.docx" --dry                   # 只盘点台词，不花钱
python translate_docx.py --docx "新剧.docx" --candidates            # 每句给2个候选（推荐在前）
python translate_docx.py --docx "新剧.docx" --model deepseek-v4-pro # 换更强的模型
```
产物：
- 单译文 → `<剧>_中上英下.docx`
- 双候选 → `<剧>_双候选.docx`（中文下：推荐行无前缀 + `候选：` 备选行）

### 第二步（B）：浏览器工作台（推荐，逐句选/改/确认）
```bash
cd E:\desk\对白翻译工作台
python server.py --docx "E:\desk\鲨鱼剧本AI测试.docx"   # 可省，默认接鲨鱼
# 或双击  启动工作台.bat
```
浏览器开 **http://127.0.0.1:8100**
- **导入剧本**：弹窗列出扫描到的 docx（E:\desk、剧本、AI work、AI download）；未翻译的剧点"翻译并载入"会先自动翻成双候选再进来。
- 每句：`A · 推荐` / `B · 备选` 点选；下方文本框可**手改**；"跳过这句"保留中文不译。
- **确认并导出成品** → 直接生成：
  - `<剧>_成品_中上英下.docx`（只含你选/改的那句英文，候选标记已去除）
  - `<剧>_成品_纯英.txt`（按集分段的纯英文，方便贴字幕）

## 剧本格式要求（当前适配的结构）
```
第1集                              ← 集标题：第X集 / 第X回
1-1 场景行（不翻译）
人物：…（不翻译）
△ 动作（不翻译）
【爆点前置】（不翻译）
角色名（情绪）：台词中文。         ← 只有这类“：台词”行会被识别&翻译
```
- 识别规则：行内含 `：`、冒号前是短角色名（≤24字）、不以 `△/【/人物` 开头。
- 翻译时自动忽略台词里的括号舞台提示（如 `（指着弗兰克）`），只译括号外的内容。
- 场景/动作/人物/集标题一律保持原样，不翻译。

## 数据/缓存文件（都放在剧本旁边，可随手删了重置）
| 文件 | 含义 |
|---|---|
| `<剧>_cache.json` | 单译文翻译缓存（逐集） |
| `<剧>_candidates_cache.json` | 双候选缓存（逐集、**按集增量落盘**，中断可续） |
| `<剧>_choices.json` | 你在工作台里的选择/手改/跳过 |
| `<剧>_成品_中上英下.docx` / `_成品_纯英.txt` | 导出成品 |

- 缓存**按集认**：翻到哪集先显示哪集，没到的集在页面显示为空。
- 删掉某个 `_choices.json` = 那部剧回到"全选推荐"的初始状态。

## 换模型 / 换翻译厂商
- 命令行：`--model` 换模型名。
- 想接 GPT-6 等 OpenAI 兼容厂商：改 `translate_docx.py` 顶部 `API = ...` 与 `SYSTEM_*` 提示词所在文件里 `API`、鉴权头 `Authorization: Bearer <key>` 的来源即可（当前 key 从 `ANTHROPIC_AUTH_TOKEN` 读）。工作台导出不受影响。

---

## 已知限制 / 坑
- **剧本必须是上面的"角色名：台词"段落结构**；表格排版、其它分集写法需小改解析（给我样例 docx 即可适配）。
- 双候选模式耗时约为单译文 2 倍（实测 10 集约 4~5 分钟），跑批建议 `--candidates` 先在命令行做（好续传），再用工作台选。
- 文件名若含 `?` 等通配符字符，ffmpeg/导入读取可能出问题；docx 读取不受影响，但导出命名建议避开。
- 服务端只认 127.0.0.1，纯本地，不会联网外传剧本。
